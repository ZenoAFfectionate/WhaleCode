Why it matters

A coding agent designed around real repository failure modes.

The project is not just a ReAct demo. It hardens the entire lifecycle: how the model calls tools, how files are protected, how large outputs are compressed, how background commands are tracked, and how benchmark submissions are judged.

FC

Native function calling instead of text parsing

Tool calls are structured JSON from the model API, avoiding fragile regex parsing of Action: text and making the ReAct loop much more reliable.

SA

Safety as a first-class tool contract

File tools validate paths against project_root, use optimistic lock metadata, produce backups, and reject conflicts before edits can overwrite human changes.

CE

Context engineering for long-horizon tasks

History, token counting, compaction, truncation, and structured context building work together so the agent can continue across multi-step programming sessions.

Core innovations

Small, clever design decisions that compound into reliability.

The strongest parts of WhaleCode are the guardrails that make an autonomous coding loop safe, observable, and recoverable under pressure.

01

Optimistic locking for file edits

Read returns file timestamp and size metadata; Write and Edit can check those values before mutating the file.

  • Detects stale reads before overwrite
  • Creates backups for surgical edits
  • Returns diffs and diagnostics after mutation
02

Bash that nudges the model toward safer tools

Shell execution supports real builds and tests, but redirects standalone ls, grep, sed, and destructive patterns toward specialized tools.

  • Secret-looking environment variables stripped
  • CPU, memory, process, and file-size rlimits
  • Background processes tracked as terminal artifacts
03

TodoWrite as a persistent planning state

Planning is not loose conversation text. It is a replace-all JSON state with validation, one active item, terminal statuses, and session snapshot integration.

  • Survives compaction and session restore
  • Rejects duplicate or conflicting tasks
  • Gives the model a minimal planning contract
04

Three-layer context compression

Micro-compaction trims old tool results, auto-compaction summarizes when token thresholds are crossed, and manual compaction can focus on a chosen subsystem.

  • Incremental token counting with cache
  • Full output persisted outside the prompt
  • GSSC context builder for structured assembly
05

TraceLogger for human and machine audit

Every major event can be emitted into JSONL and a readable HTML trace, with secret redaction and run statistics for review.

  • Session start and metadata events
  • Tool call/result timeline
  • HTML reports for debugging and demos
06

Web console for operational control

The web surface streams agent events over SSE, controls vLLM processes, switches models, launches benchmarks, and exposes trajectory detail.

  • No heavy framework dependency
  • Model discovery and launch helpers
  • Benchmark history and trajectory panels

Evaluation lab

Benchmarks are treated as product infrastructure, not afterthoughts.

WhaleCode includes runners for programming, math, and repository repair datasets. The benchmark layer records progress, preserves trajectories, supports resume, and standardizes heterogeneous task formats through adapters.

Controlled submission loop

Instead of a one-shot answer, each benchmark can run multiple controlled rounds. The agent submits, sandbox evaluation produces structured feedback, and the next prompt contains the actionable failure signal.

SubmitAgent writes or returns a candidate solution.
SandboxStatic checks and OS-level resource limits apply.
EvaluateAdapters run assertions, hidden tests, stdin, or functions.
FeedbackFailures are clipped and transformed into a retry prompt.
RetryAgent improves within a fixed step and round budget.

Implementation snapshot

The codebase shows production thinking in multiple layers.

The most important modules are cohesive: CodeAgent wires repository behavior, ToolRegistry normalizes execution, file tools protect edits, and benchmark runners evaluate the system end to end.

code/agents/code_agent.py

Repository-aware CodeAgent with default tool registration, workspace prompt, compaction API, and isolated sub-agents.

code/tools/builtin/file_tools.py

Read/Write/Edit/Delete with path resolution, optimistic locks, backups, conflict detection, and structured diagnostics.

code/benchmark/base.py

BenchmarkCodeAgent plus controlled submission rounds, event capture, progress updates, and trajectory persistence.

web/server.py

Zero-dependency HTTP/SSE control plane for model management, agent jobs, benchmarks, sessions, and trajectories.
